## Quyết định

- Thêm feature API `Drafting/DocumentCatalog` theo vertical slice: controller mỏng,
  service scoped giữ query/validation/quy tắc nghiệp vụ và DTO tách khỏi EF entity.
- GET yêu cầu `BusinessAccess`; POST/PATCH chỉ dành cho `Administrator`. Danh sách
  hỗ trợ paging, lọc active và sắp xếp ổn định; template chỉ được xem là khả dụng
  khi cả template lẫn loại cha đều active.
- PATCH dùng presence flag để phân biệt field bị bỏ qua với `null`; chỉ
  `description` nhận `null`. Chuỗi được trim, còn code giữ nguyên hoa/thường.
- Chuẩn hóa conflict unique từ cả pre-check và database constraint thành `409`.
  Việc tạo, đổi loại hoặc kích hoạt template bắt buộc loại cha tồn tại và active;
  vô hiệu hóa loại không cascade xuống template.
- Giữ `TemplateContent` là plain text. `FormatRules` là JSON object lưu nguyên dạng
  JSONB; schema yêu cầu `version` là số nguyên dương, `rules` là mảng và mỗi rule có
  `code` không rỗng cùng `required` boolean. Thuộc tính mở rộng ở root/rule được giữ;
  lỗi cấu trúc trả `422`, còn JSON HTTP sai cú pháp vẫn trả `400`.
- UI dùng URL query để giữ filter/page khi điều hướng, tải đủ các trang loại văn bản
  cho bộ chọn, chỉ cho reassign sang loại active và giữ nguyên form khi gặp `409`/
  `422`. Trình soạn `FormatRules` dùng textarea monospace, pretty-print và kiểm tra
  cú pháp/schema ở client trước khi gọi API.
- T2-01 chỉ cung cấp contract và dữ liệu template khả dụng. T3-01 vẫn phải kiểm tra
  lại trạng thái active của type/template khi tạo văn bản đi.
