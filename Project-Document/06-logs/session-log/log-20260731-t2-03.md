## Quyết định

- Thêm `IAttachmentService` và `IAttachmentStorage`; provider local dùng object key do
  máy chủ sinh từ GUID của document/attachment và extension đã xác thực. Root mặc định
  là `App_Data/attachments`, ngoài web root và được gitignore.
- Upload qua file tạm rồi atomic move; lỗi ghi metadata xóa file bù trừ. Xóa file dùng
  quarantine và khôi phục nếu transaction database thất bại. Không trả storage key,
  extracted text, extraction error hoặc đường dẫn vật lý trên wire.
- Giới hạn mặc định 10 MiB được kiểm tra ở request/form limit và service. Chỉ nhận PDF,
  DOCX, XLSX, JPG/JPEG, PNG; extension phải khớp signature hoặc cấu trúc thực tế.
- PDF/DOCX/XLSX tạo `Pending`; ảnh tạo `Unsupported`. Mọi trường nội dung/lỗi/thời điểm
  trích xuất giữ null trong T2-03.
- Migration `AddIncomingAttachments` chỉ tạo parent incoming bắt buộc, FK `RESTRICT`,
  check constraint và index cần thiết. Không có outgoing column, GIN index hoặc binary
  PostgreSQL; T3-01 sẽ thêm parent outgoing và constraint đúng một parent.
- GET download dùng `BusinessAccess`; upload/delete chỉ Clerk và bị khóa khi văn bản
  đã `Completed`. Incoming detail trả attachment thật, nested uploader và thứ tự
  `uploadedAt DESC`, sau đó `id`.
- SCR-009 dùng Ant Design Upload và bảng metadata. Download đi qua request có JWT và
  object URL tạm; upload/xóa chỉ hiện cho Clerk khi chưa Completed.
